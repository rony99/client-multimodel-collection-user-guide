# cc-gateway 使用说明（发行包）

本目录是**已编译好**的本地网关包，目标机器**不需要安装 Go**。  
作用：让 Claude Code 的请求经本地网关转发到 **GLM / 千问 / 官方 Claude 订阅**，并按 session 抓包落盘。

---

## 一、使用前准备（网络）

1. **安装并登录 Claude Code**  
   终端能运行：`claude --version`

2. **网络与 VPN（重要）**  
   - 使用 **A（GLM）** 或 **B（千问）** 时，本机必须能访问厂商云端 API（如 `your-glm-provider.example`、`your-qwen-provider.example`）。  
   - 若你所在网络需代理才能出国/访问这些云，请先**开启 VPN**。  
   - 请将 VPN 设为 **Tun 模式（全局虚拟网卡 / 增强模式）**，不要仅用「系统代理 / 仅浏览器代理」：  
     - Claude Code 与本网关都是命令行/本机进程，很多场景**不会**自动走「仅 HTTP 代理」；  
     - Tun 模式可让网关访问上游时走 VPN 通道，减少超时、TLS 失败、连不上 API。  
   - 使用 **C（官方 Opus 订阅）** 时，同样需要本机能访问 `api.anthropic.com`；在受限网络同样建议 VPN + Tun。

3. **可选环境变量**（不写 YAML 也能临时覆盖）  

| 变量 | 说明 |
|------|------|
| `CCG_LISTEN_ADDR` | 监听地址，默认 `:3001` |
| `CCG_DATA_DIR` | 强制覆盖抓包根目录 |
| `CCG_CONFIG` | 等价于 `-config` 路径 |

## 三、配置（providers.yaml）

1. 复制示例（**不要**把真实 key 写进会上传的 example 文件）：

```bash
# macOS / Linux
cp providers.example.yaml providers.yaml

# Windows PowerShell
Copy-Item providers.example.yaml providers.yaml
```

2. 用编辑器改 `providers.yaml`：

```yaml
# 当前启用：A=GLM | B=千问 | C=官方 Opus（订阅透传）
active: A

# 可选：抓包根目录。留空 = 当前用户主目录下的 .claude_lproxy/projects
root_dir:

A:  # GLM
  url: https://your-glm-provider.example/api/anthropic
  key: 你的-GLM-API-Key

B:  # 千问
  url: https://your-qwen-provider.example/apps/anthropic
  key: 你的-千问-API-Key

C: {}  # 官方订阅：无需 url / key
```

| `active` | 含义 | 必填 | Claude 侧模型映射（网关自动写入 settings） |
|----------|------|------|------------------------------------------|
| `A` | GLM | `url` + `key` | opus/sonnet/haiku → **glm-5.2** |
| `B` | 千问 Qwen | `url` + `key` | opus/sonnet/haiku → **qwen-3.7-max** |
| `C` | 官方 Anthropic | 无（需本机已登录 Claude 订阅） | 不改官方模型名 |

默认抓包目录（`root_dir` 留空时，按系统用户动态生成，不写死用户名）：

- macOS：`/Users/<用户名>/.claude_lproxy/projects`
- Linux：`/home/<用户名>/.claude_lproxy/projects`
- Windows：`C:\Users\<用户名>\.claude_lproxy\projects`

结构：

```text
~/.claude_lproxy/projects/<sessionId>/<callId>.json
```

`<sessionId>` 与 Claude Code 本地会话一致（请求头 `X-Claude-Code-Session-Id`，与 `~/.claude/projects/<项目>/<sessionId>.jsonl` 同名）。

## 四、启动网关

先切换到本目录，再选与本机架构匹配的二进制：

### macOS

```bash
# Apple Silicon（M 系列）
chmod +x ./cc-gateway-arm64
./cc-gateway-arm64 -config ./providers.yaml

# Intel Mac
./cc-gateway-amd64 -config ./providers.yaml
```

### Linux

```bash
chmod +x ./cc-gateway-amd64   # 或 arm64
./cc-gateway-amd64 -config ./providers.yaml
```

### Windows（PowerShell）

```powershell
.\cc-gateway-amd64.exe -config .\providers.yaml
# 或 ARM: .\cc-gateway-arm64.exe -config .\providers.yaml
```

启动成功时终端会类似：

```text
cc-gateway ready (...)
  active:       A (GLM)
  listen:        :3001
  data dir:      /Users/<你>/.claude_lproxy/projects
  upstream:      https://your-glm-provider.example/api/anthropic
  model aliases: opus=glm-5.2 sonnet=glm-5.2 haiku=glm-5.2
  pinned model:  glm-5.2

Start Claude Code with:
  claude --settings /绝对路径/providers.claude.settings.json
```

同时会生成（与 yaml 同目录、勿提交密钥）：

`providers.claude.settings.json`  

其中会把 `ANTHROPIC_BASE_URL` 指到本机网关（如 `http://127.0.0.1:3001`），A/B 还会写入 token 与模型 ENV。

**注意：** 改 `providers.yaml` 后需**重启网关**，再按新打印的命令启动 / 重启 Claude Code。

## 五、启动 Claude Code

**保持网关终端在运行**，再开一个终端：

```bash
# 使用网关刚打印的路径（示例）
claude --settings /path/to/providers.claude.settings.json
```

建议在真正工作的项目目录下执行 `claude`。  
会话目录对照：

| | 路径示例 |
|--|--|
| Claude Code 本地会话 | `~/.claude/projects/<项目 slug>/<sessionId>.jsonl` |
| 网关抓包 | `~/.claude_lproxy/projects/<同一 sessionId>/*.json` |

### 验证

```bash
# 网关是否在听（默认 3001）
curl -s http://127.0.0.1:3001/health

# macOS/Linux 状态命令（需二进制同目录）
./cc-gateway-arm64 status -config ./providers.yaml
```

抓包日志中：

- `Authorization` / `x-api-key` 等应为 `"[redacted]"`，**不会存明文 Bearer/Token**
- `sessionId` 与 Claude Code 会话 UUID **保留**

## 六、切换方案

1. 改 `providers.yaml` 的 `active`（及 A/B 的 url/key）  
2. 停止网关（终端 Ctrl+C）  
3. 重新启动网关  
4. 用新打印的 `claude --settings ...`（或重启已打开的 Claude Code）

## 七、常见问题

**连不上上游（超时 / TLS / DNS）**  
- 确认 VPN 已开且为 **Tun 模式**  
- 浏览器能开厂商控制台不代表 CLI 一定通；Tun 更适合本场景  
- `curl -I https://your-glm-provider.example` 可粗测连通

**`/model` 仍是 Opus/Sonnet 名字**  
- 正常：Claude Code UI 别名不变；A/B 时实际会映射为 `glm-5.2` / `qwen-3.7-max`  
- 以抓包里的 `request.body.model` 为准

**抓包目录对不上 Claude Code**  
- 不要长期设置错误的 `CCG_DATA_DIR`  
- 核对 `X-Claude-Code-Session-Id` 与两个目录名是否一致

**端口被占用**  

```bash
CCG_LISTEN_ADDR=:3002 ./cc-gateway-arm64 -config ./providers.yaml
```

会重新生成 settings 里的端口。

**方案 C 官方订阅 401/403**  
- 先在本机正常登录 Claude（Max/Pro），再走网关透传

## 八、安全说明

- `providers.yaml` 含密钥，**勿提交 Git / 勿分享**  
- 抓包 JSON **会脱敏**认证头；但仍可能含对话内容与代码上下文，注意保管  
- 生成的 `*.claude.settings.json` 在 A/B 模式下含 token，同样勿外传
